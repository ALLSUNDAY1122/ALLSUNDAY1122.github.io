Candidate identity = exact full Git commit SHA, tree SHA, app ID 6802119268, bundle ID com.allsunday1122.tourokuhanbaisha, marketing version, build number when applicable, archive SHA-256, ASC build ID. Record execution SHA and candidate SHA separately. No proof from merely matching branch or build number. If later documentation-only changes are to reuse evidence, require explicit independently checked build-input manifest equivalence; never assume it.
Evidence record: gate, type, subject identity, observed time, source/run/job/artifact ID, repository path and digest, result, scope, verifier, limitations. Resolve evidence to source, check integrity and run conclusion, and reject untrusted or missing evidence, stale SHA, wrong app/build, contradictory evidence, or self-declared PASS. Evidence input must be read-only and independently retrieved from trusted providers; untrusted PR artifacts cannot attest themselves. Use canonical serialization and SHA-256. External evidence verification is a separate stage; no automatic promotion until implemented/tested. Store raw evidence separately from summary.
