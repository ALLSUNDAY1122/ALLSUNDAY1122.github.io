## ループエンジニアリング

変更 → 対応品質ループ起動 → 監査 → FAIL修正 → 再監査 → PASSまで反復 → 次工程。

一度PASSした監査でも対象データが変更された時点でPASSを失効する。必修・一般・状況設定の3班がPASSし、720問統合監査・メディア権利監査・専門監査がPASSするまで、製品版全体を完成扱いしない。

## 隔離・採点例外

図版依存、公式採点特例、現行知識との齟齬懸念、専門監査対象は通常問題と分離する。

特に第113回の採点特例は年度別 `examConfig` で公式取扱いを保持し、採点除外問題へ独自正答を設定しない。図版依存問題は権利・表示監査が終わるまで出題しない。

## 模試

各試験回240問の製品データが監査済みになった場合のみ「240問模試完成」と扱う。未完成データを240問あるように見せる水増しは禁止する。

本番模試では即時採点をOFFにし、必修基準、一般＋状況設定基準、年度別採点例外をデータ駆動で判定する。

## 課金・iOS

問題監査と製品解放ゲートの後に StoreKit 2 を統合する。購入・復元・無料範囲・失敗時挙動・価格表示を課金監査し、Privacy、App Storeメタデータ、公開サポートページ、TestFlight実機確認へ進む。
