## 2. 準備・共通ルール

1. 検証承認済みRCの**正確な**GitコミットSHA、ビルド番号、配布元（TestFlight／開発署名等）、iPhone機種、iOS、実施日時（JST）を記録する。Simulatorやブラウザの結果を実機のPASSに転記しない。
2. 実機のApple Accountと、購入テストに使うSandbox Apple Accountを混同しない。TestFlightのIAPは原則Sandboxテストであり、実際の請求がないことをApple公式説明と端末の表示で確認する。開発署名時はXcodeのローカルStoreKit設定を誤って有効にしていないか記録する（`Review.storekit`はSimulator用のローカル設定）。**本番Apple Accountを使う実購入は行わない。**
3. 開始前にアプリの無料状態、Premium表示、既存購入権利と学習進捗をスクリーンショットで残す。購入系の再現性が必要なら、未購入のSandboxテスターを別途用意する。既存データの消去・アプリ削除・Sandbox履歴の消去は明示的なバックアップと同意なしに行わない。
4. ネット接続を確保し、App Storeのサインイン状態と販売商品取得を確認。購入操作中の画面、システムダイアログ（機密情報をマスク）、操作後の状態、アプリ再起動後の状態を保存する。Apple ID・パスワード・領収書番号・取引IDの全文は公開GitHubに置かない。
5. ケース実施前に前提条件を記入し、**期待結果と実測結果を区別**する。実行していない場合`NOT_RUN`、環境や審査待ちで実施できない場合`BLOCKED`、検証したが断定不能なら`UNVERIFIED`とする。PASSは期待動作と証跡の両方が揃ったときのみ。
6. 課金試験は各ケースの前にテストアカウントの権利状態を確認。返金・取り消し・購入待機の操作は購入・復元テストと順序が干渉するため、可能ならテスターを分ける。返金処理時間やAsk to Buyの可否はApple側制約に依存し、実行できなければ無理に代替しない。

### 判定値と証跡ファイル規則

`PASS`＝実機で実施し基準を満たした、`FAIL`＝実機で再現した不具合、`BLOCKED`＝ビルド・Sandbox・承認など前提未達、`UNVERIFIED`＝操作はしたが必要な確認ができない、`NOT_RUN`＝未着手。任意のケースで前提未達をPASSとしない。

スクリーンショットは例として `evidence/device/YYYYMMDD/FP3-DV-01-before.png`、`...-after.png` のように識別する。個人情報をマスクしたものだけを共有し、実ファイルが存在しないパスは記載しない。障害時は再現手順、期待と実際、時刻、頻度、動画またはスクリーンショット、必要なら匿名化したStoreKitログを残す。

## 3. ケース別の実施手順・合否基準

### DV-01 学習・進捗保存（未購入／購入済み）

**前提**：対象RCを実機に導入し、問題と解説を読み込める。購入前後それぞれの権利状態を記録。

**操作**：
1. 起動・ホームを表示し、2026年度の無料演習を開始する。問題ID／年度／分野を記録。
2. 1問回答して採点と解説を確認。解説の出典リンク、公表年月、問題番号、加工表示、適用基準日を画面で確認する。
3. 回答直後にアプリを完全終了し再起動、同じ設問へ復帰。正誤履歴・進捗・苦手状態を確認する。
4. 同じ回答の重複集計がないことを確認し、苦手問題を3回連続正解した場合の卒業処理も可能な状態で確認する。
5. 未購入時に2024／2025年度、分野別、苦手復習をタップし、Premium案内が表示され、ロック対象の問題が開始されないことを確認。
6. 購入済みテスターで同じ導線を操作し、Premium対象（2024・2025年度、6分野、苦手復習）が使えることを確認。178問の範囲表示と隔離2問の不露出は、監査記録と照合できる範囲で別途確認する。

**PASS**：無料・有料の境界が正しく、回答・採点・解説・再起動後の復帰が一致し、二重加算がない。進捗の表示に矛盾がなく、出典・基準日が確認可能。**FAIL**：データ消失、二重加算、権利境界を越えたアクセス、表示欠損、クラッシュ等。再現を記録。

### DV-02 購入（新規Sandbox／非消耗型）

**前提**：未購入のSandboxテスター。対象商品が配信・取得可能。端末で`Review.storekit`のローカル価格を参照していない。

**操作**：
1. ロックされた学習機能または「設定 > Premiumについて」を開く。
2. 購入画面に「買い切り」、商品価格、購入・復元・閉じる操作が表示されることを確認。端末表示価格と対象販売設定を照合し、製品IDを記録。
3. 購入を押し、Sandboxのシステム購入確認を完了する。連打せず一回の取引を確認。
4. Premium案内が閉じ、ロックされていた年度・分野・苦手復習が開放されることを確認。アプリ完全終了・再起動後も権利が維持されることを確認。
5. 再度購入画面を呼ぶ操作が可能なら、同じ買い切り商品に対する意図しない二重請求・重複権利付与がないことを確認（追加決済を強制しない）。

**PASS**：対象商品が正しい価格で取得でき、検証済み購入後にPremiumが有効となり再起動でも継続し、誤重複購入がない。**FAIL**：誤商品・誤価格・購入成功なのに未解放・再起動で権利消失・二重課金など。`product_unavailable`や通信障害など前提不備は原因とともに`BLOCKED`または`UNVERIFIED`とし、安易にFAIL/PASSへ割り振らない。

### DV-03 購入キャンセル

**前提**：未購入のSandboxテスターで購入画面・システムシート表示が可能。

**操作**：
1. 購入ボタンを押してAppleの確認シートを表示。
2. シート側でキャンセル（購入を確定しない）。アプリへ戻る。
3. Premiumが未解放のままであること、購入画面を閉じたり再表示したりできること、購入ボタンが操作可能な状態に戻ることを確認。
4. 同じ手順をもう一回行い、ボタンが永久無効にならないことと二重の購入シートが出ないことを確認。

**PASS**：決済なし・権利未付与・UI復帰・再購入可能。**FAIL**：購入済み扱い、操作不能、重複ダイアログ、クラッシュ等。

### DV-04 承認待ち（pending）

**前提**：Apple公式のSandboxでAsk to Buy等の承認待ちが再現できるテスト設定と、承認者を操作できる環境。設定方法・可用性を実行前に確認。通常の個人Sandboxテスターで再現不能なら`BLOCKED`。

**操作**：
1. 未購入テスターでPremium購入を開始し、承認待ちとなる条件で確定する。
2. アプリに「購入承認待ち」が示されることと、Premiumが**未解放**のままであることを確認。画面を閉じ、再起動しても誤解放がないか確認。
3. テスト環境で承認可能になった後に承認操作を行い、アプリを再表示／再起動し、StoreKitの取引更新に応じてPremiumが解放されることを確認。却下も検証する場合は別テスターまたは別サイクルで、未解放を確認。
4. 長時間待機や未通知の状況は時刻とともに記録する。確認できない結果を成功扱いしない。

**PASS**：pending中に誤付与せず、承認後に検証済み取引に従って解放、却下時は未解放。**FAIL**：pendingで即解放、承認後も取引反映不能等。Apple側で承認・却下を操作できず後続が見られなければ`BLOCKED`／`UNVERIFIED`。

### DV-05 購入復元

**前提**：同一Sandbox Apple Accountで対象買い切り商品を購入済み。別の未購入アカウントと混在させない。

**操作**：
1. 購入済み権利が存在する状態で「設定 > 購入を復元」、必要ならPremium画面内の「購入を復元」をそれぞれ試す。
2. Appleのアカウント確認が表示された場合は正しいテスターで対応。Premiumが維持され、二重支払いがないことを確認。
3. アプリ再起動後の権利を確認。アプリ再インストールを試す場合は**学習履歴が消える可能性を了承・退避してから**行い、購入権利と学習履歴は別々に判定。
4. 未購入Sandboxテスターでは復元によってPremiumが付与されないことも確認。ネットワークエラー時は後で再試行可能か確認。

**PASS**：購入済みテスターの正規権利のみ復元し、未購入テスターには付与せず、追加請求もない。**FAIL**：正規権利の復元不能、未購入者への権利誤付与、連打で操作不能等。Apple Account不一致・通信不通は区別して記録。

### DV-06 返金・権利取消（Sandbox）

**前提**：専用Sandboxテスターに購入済み権利があり、返金試験の可否と方法がApple公式ツール・Sandbox設定で確認できること。通常のユーザー向け本番返金申請をテスト目的で行わない。Sandboxで返金操作が不可能なら`BLOCKED`。

**操作**：
1. 返金前にPremium有効・対象商品ID・時刻・演習へのアクセスを記録。
2. Appleが提供する該当テスト環境の返金／取引取消手段を用いて対象取引を取消し、反映まで待つ。使用した公式操作経路と実際の返金／revocation状態を記録。Sandbox購入履歴の単純なリセットは「返金確認」の代替としない。
3. アプリを起動・再表示してStoreKitの権利更新を待ち、必要に応じて再起動と「購入を復元」を実施。
4. Premiumが解除され、2024・2025年度・分野別・苦手復習が無料境界に戻り、2026年度無料学習は引き続き利用できることを確認。再起動後も不正な権利が戻らないことを確認。
5. 学習データの保持とPremium権利取消は別の論点として記録し、返金で学習履歴が当然消えるとは判定しない。

**PASS**：返金／取消が証跡で確認され、検証済み権利が失効しPremiumが再有効化されず、無料部分が継続利用できる。**FAIL**：失効済みの権利でPremiumが続く、無料部分も利用不能、復元で失効権利が復活する等。返金結果の確認不能は`UNVERIFIED`、返金手段自体がない場合は`BLOCKED`。

## 4. 実施順と重要な分離

推奨順：DV-01（無料）→DV-03（キャンセル）→DV-02（新規購入）→DV-01（有料）→DV-05（購入済み復元）。DV-04（pending）とDV-06（返金）は可能なら独立Sandboxテスターで実行。返金後のDV-02／DV-05は前提が変わるため、結果を流用しない。

実機チェックと並行して、実機ホーム画面で正本AppIconを確認し、公開される`privacy.html`・`terms.html`・`support.html`のHTTPS/HTTP 200と設定画面からの遷移を別途記録する（公開前は`BLOCKED`）。これらはDV-01〜06のPASSだけで完了扱いにしない。

## 6. 完了判定と引継ぎ

実機StoreKitの検証完了は、DV-01〜DV-06の必要シナリオに実測・証跡があり全てPASSであることを原則とする。Appleのテスト環境の制約でDV-04／DV-06を再現できない場合、**未検証であることを維持し**、代替の技術的根拠・リスク・審査への影響を別途判断する。1件でもFAIL、重要ケースのBLOCKED／UNVERIFIEDが残れば「実機全項目PASS」と記載しない。

実施者は本書の台帳と証跡を更新し、`RELEASE_STATUS.md`の実機検証欄へ**確認できた事実だけ**を転記する。内容180問監査・権利条件・公開3 URL・ASCのプライバシー/契約等・正確なRCビルドは独立した提出ゲートであり、実機手順書の作成やSimulatorビルド成功をもってRelease／TestFlight送信・App Review提出を認めない。アップロード、Apple処理完了、TestFlight配布、審査提出、審査待ち、公開はそれぞれ分けて追跡する。
