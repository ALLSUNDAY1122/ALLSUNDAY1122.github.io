# 明細CSV直し v1.1.1

無料・登録不要の、円建て明細CSV正規化ツールです。サーバー、ビルド、ライブラリのインストールは不要です。ZIPをすべて展開して **index.html** を現行Chrome / Edge / Firefox / Safariで開いてください。CSS・JSはindex.htmlと同じ場所に置きます。PDF・外貨・小数金額は未対応です。

## 使い方

1. 金融機関とCSVを選びます。「架空データで試す」でも動作確認できます。
2. 自動判定した文字コードと見出し行を確認します。文字化け時はUTF-8またはShift_JISを明示してください。
3. 日付・摘要・金額・取引後残高の列を割り当てます。**入出金1列と入金/出金2列の併用は不可**です。不要な列を「なし」にしてください。
4. 1列方式のプラスの意味を選びます。銀行は通常入金、楽天カードは利用額（出金）を表すという初期設定です。これは**推定**のため実データに照らして確認してください。返金の負号は逆向きに変換します。
5. 入力が新しい順なら「新しい順」を選びます。全レコードを逆転する方式で、日付による自動ソートは行いません。同日内の並びも重要です。
6. 最も古い明細の直前残高を任意で入力し、照合します。
7. エラー・赤い不一致・黄色い注意を確認し、出力先を選んで確認チェックを入れ、「出力ファイルを作る」→保存リンクを押します。

元のファイルは変更しません。設定変更時は結果と保存リンクを無効化します。CSVを修正した場合は再選択してください。先頭50レコードから見出しを選べます。ヘッダーがないCSVには見出し行を追加してください。空レコードは無視しますが、合計行、説明行、補足行、カードの2行明細は黙って捨てずエラーにします。必要な修正は元CSVで行います。

## 出力と取り込み先

| 出力 | 仕様・取り込み方法 |
|---|---|
| freee 銀行 | UTF-8 BOM付き、取引日/出金額/入金額/残高/取引内容。対象の銀行口座から「明細アップロード」。列対応を確認して確定。 |
| freee カード | UTF-8 BOM付き、取引日/取引金額/取引内容/カードラベル。利用額は正、返金は負。対象のカード口座から「明細アップロード」。同期済みカードラベルが必要なら入力。 |
| マネーフォワード | **クラウド会計・確定申告の仕訳帳インポート用27列CSV**（UTF-8 BOM付き）。会計帳簿→仕訳帳→インポート→仕訳帳。明細連携用ExcelテンプレートやマネーフォワードME用ではありません。 |
| 弥生 | スマート取引取込用7列CSV。Shift_JIS（ブラウザのCP932互換変換）、各ファイル190,000バイト未満。CSVファイル取込で日付/入金/出金/摘要を割り当て、1行目を見出しとして除外。分割ファイルはすべて個別に保存・取り込み。仕訳日記帳用25列ではありません。 |

MFは明細から相手科目を決定できないため、口座科目、相手科目、税区分を利用者が指定します。全行へ同じ科目・税区分を適用するため、用途・税区分が異なる明細は元CSVを分けてください。初期値は「普通預金 / 未確定勘定 / 対象外」。カード口座なら「未払金」等の実際の負債科目に変更します。銀行入金は口座を借方、出金は貸方。カード返金も内部の入金として扱います。税額とインボイス区分は空欄。MFは空欄インボイスを適格として扱うため、課税取引では取り込み前に必ず区分・税額を確認してください。本ツールは税計算や経費判定をしません。

全サービスで、対象口座、会計年度、科目の登録状況、列対応、最終プレビューの確認は必要です。仕様に基づくファイル生成を検証していますが、実アカウントへの取込は未検証で、全契約プラン・将来の仕様変更までの互換性保証はありません。既存の自動連携明細との重複にもご注意ください。

## v1.1.1の数式対策

純粋な数値は先頭アポストロフィを付けず保持します。任意の先頭マイナス、整数、正しい3桁のカンマ区切り、小数点を受け付けます（例：`-1500`、`-1,500`、`-1500.50`、`-.5`）。先頭プラス、空白、指数表記、複数の小数点、不正な桁区切りは例外にしません。`-1+1`、`-cmd`、`=SUM(1)`等は従来どおり無害化します。末尾改行も数値として認めません。数式対策で小数文字列を保持することと、明細金額の受入れ条件は別です。本ツールの明細金額は引き続き円整数のみです。

## 残高検証

内部は「入金プラス・出金マイナス」の安全な整数円で統一します。直前残高 + 入出金を累積計算し、元CSVの取引後残高と比較します。

- 直前残高がなければ、最初の残高付き行は基準行となり、その行自身は未検証です。
- 不一致があっても元残高に合わせ直さず、後続も累積計算します。元残高は自動修正しません。freee出力の残高には元CSVの値を保持します。
- 残高列がなくても、直前残高があれば再計算だけは可能です。直前残高もなければ照合不可です。
- エラー行があれば、その後の残高検証は停止し、ファイル出力も停止します。エラー行を自動除外しません。
- 不一致・重複候補・検証不可は表示し、利用者の確認後に出力可能です。重複候補は日付/金額/摘要の一致であり、削除しません。
- カードの未払債務残高は銀行残高と符号が逆です。カードの「翌月繰越残高」などを銀行の取引後残高として割り当てないでください。カード利用CSVは通常残高検証不可です。

## 文字・金額・安全性

UTF-8はBOM有無両方に対応。厳密なUTF-8デコードに失敗したときShift_JISとして読みます。ASCIIだけならUTF-8扱いです。双方で解釈できるバイト列は完全な自動判定ができないため、手動変更を用意しています。UTF-16は非対応です。

全角数字、桁区切り、円記号、▲/△、各種マイナス、括弧負数を正規化します。西暦4桁、年月日/スラッシュ/ハイフン/ドット/8桁日付、明治〜令和とM/T/S/H/Rに対応。元号境界・うるう年を検証し、年のない日付や曖昧な西暦2桁は拒否します。別々の年月日列は未対応です。金額は円整数のみ、2列方式では正数のみ。入金と出金の双方が非ゼロ、0円、欠損、不正文字、整数範囲超過はエラーです。

データは端末のメモリ上だけで処理。ネットワーク送信、アクセス解析、外部CDN、Cookie、localStorageは使用しません。CSPで接続を拒否します。外部リンクを開く操作ではリンク先に通信します。画面はtextContentで描画し、CSV出力の全セルを最終段で検査し、= / + / - / @ / タブ / CRで始まる値に先頭アポストロフィを付けます。空白で隠した数式先頭も対象です。純粋な数値だけは例外とし、負数金額・カード返金の符号を保持します。CSVのセル内改行は、数式先頭の無害化を行った後に空白にします。SJIS非対応文字（絵文字など）と弥生の摘要80文字・金額9桁超は黙って置換・切断せず拒否します。入力上限10MiB、展開後UTF-8換算テキストも10MiB。CSVレコード数上限20,000（見出し・空行・前置き行を含む）、列数上限200、1セル上限10,000 UTF-16コード単位。引用符内の改行は同一レコードとして数えます。ページ表示は100件ずつです。入力値・ファイル名はエラーメッセージに含めません。未知の例外は固定メッセージに置き換えます。明細値は通常プレビューだけに表示し、エラー欄には含めません。ログへ出力しません。

## 推定の一覧

1. **ゆうちょ**：列名候補、残高列名、プラス金額の向き。個人向け実CSV全仕様の公開確認なし。
2. **楽天銀行**：個人向けを含む列候補、プラス金額の向き。法人向けの「取引日 / 入出金(円) / 残高(円) / 入出金先内容」は公開確認済みですが、全形式に一般化はしません。
3. **住信SBI**：列名候補・符号。現行サービス名や画面の違いによる形式差は未検証。
4. **PayPay銀行**：列名候補・符号。時刻付きや別サービスの形式差は未検証。
5. **楽天カード**：列名候補、利用プラス・返金マイナスの扱い。分割・リボ・2行表記は自動統合しません。
6. **全機関・汎用共通**：先頭50レコードからの日付等の見出し一致による見出し行・列割り当ての自動提案。汎用を含め同じ候補辞書を使います。金融機関選択は主にカードの初期符号を切り替え、実CSVの厳密な識別はしません。

いずれもUIとcore.jsのコメントに「推定」と明記。test/fixturesの金融機関別CSVもすべて架空の推定レイアウトであり、銀行公式サンプル・実データではありません。出力仕様の根拠と確認範囲はSOURCES.mdを参照。

## テスト

Node.js 20以上（実行環境：24.19.0）で、依存のインストールなしに実行できます。

```sh
npm test
# または
node --test test/*.test.cjs
```

テストは金額/日付の境界、UTF-8/BOM/Shift_JIS、5入力例、1/2列方式、カード返金、残高、逆順・重複、CSV引用符、破損行、各出力列順、文字コード、弥生分割、数式防止とUIイベントの一連の流れを検証します。UIテストは最小DOMモデルによる機能テストです。実ブラウザの描画、ファイル選択ダイアログ、各会計サービスの実取込は未検証です。結果ログはtest-results.txt。セキュリティ要件(a)〜(f)の検証結果はSECURITY-CHECKS.md。
