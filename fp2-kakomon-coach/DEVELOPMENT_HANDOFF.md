# FP2級 過去問コーチ 開発引継ぎメモ（DEVELOPMENT_HANDOFF）

作成日: 2026-08-02　作成者: Claude（本開発担当AI、ユーザー就寝中に独立して完成させた）

## 1. 今回の主要な設計判断

### 1-1. 回答UIを「4択タップ」に変更した理由（重要）
FP3級版は○×の二択であったため「右スワイプ＝○、左スワイプ＝×」という直感的なジェスチャーが成立した。しかしFP2級学科試験は**四答択一式**であり、4つの選択肢のうちどれが正解かを選ぶ形式のため、スワイプ方向と選択肢を1対1で対応させることができない（4方向スワイプは誤操作率が高く、誤答時のストレスが大きいと判断した）。

このため、今回は以下の設計に変更した。
- 基本操作：4つの選択肢カードを**タップして選ぶ**。
- 画面下部に「わからない」ボタンを常設（FP3級と同じ役割：弱点登録のトリガーとして機能）。
- スワイプ操作は実装していない（ページ送り演出も含め、今回は省略した）。理由：タップだけで完結する方が学科試験の形式に忠実であり、実装・検証の両面で確実性を優先したため。将来的に「問題カードの左右スワイプでページ送り」を演出として追加することは可能だが、必須機能ではないと判断し、今回のスコープからは外した。

### 1-2. 「今日の10問」の抽出ロジック
初回は6分野からラウンドロビンでバランス良く10問抽出し、2回目以降は「未出題優先→弱点優先→既出非弱点」の順に優先度をつけてシャッフルしている。これはカレンダー日付（実際の「今日」）に紐付けたロジックではなく、**アプリ内の実行回数**（`todayTenRunCount`）に基づく設計とした。理由：完全オフライン・サーバーなしという制約下で「同じ日に複数回開いた場合の挙動」を過度に複雑化させないため。将来、日付ベースのローテーション（1日1回だけ「新しい10問」が生成される等）に変更したい場合は、`STATE.todayTenRunCount`を日付キーに置き換えることで対応可能。

### 1-3. 完走カウントの仕様
「セッションに含まれる全問題に回答した時点」で完走1回とし、正誤は問わない。これはSPEC.mdに明記した通り、ユーザー指示の「完走の定義」に忠実に実装した。

### 1-4. 弱点判定ロジック
誤答・わからない→弱点登録＋連続正解数0。正解→連続正解数+1、3に到達で弱点解除。この仕様は`scripts/tests/algo_test.js`で自動テスト済み（後述）。

## 2. 既知の問題・未実装機能

1. **スワイプ演出は未実装**（上記1-1参照）。タップのみで完結する。
2. **「今日の10問」はカレンダー日付に連動しない**（上記1-2参照）。同じ端末で1日に何度実行しても「初回/2回目以降」の判定は累積実行回数ベース。
3. iPhone実機・Safariでの実地確認は未実施（後述TEST_RESULTS.md参照）。CSSレベルでは横スクロールが発生しない設計（`max-width:520px`のコンテナ、`box-sizing:border-box`、長文選択肢に`word-break`を適用）にしているが、実機での最終確認は次工程が必要。
4. `outputs/fp2-kakomon-coach/questions/build.py`という114KBのファイルが残存している。これは60問JSON作成を担当したサブエージェントが使った生成スクリプトの残骸で、サンドボックスの権限問題により削除できなかった。**成果物としては無害**（question_bank_fp2.jsonやアプリ本体からは一切参照されない）。次工程で問題があれば削除して差し支えない。
5. 同様に `outputs/fp2-kakomon-coach/scripts/_check/` ディレクトリに、検証作業中に生成した中間ファイル（`json_block.json`, `js_block.js`, 中断した`npm install jsdom`のnode_modules）が残っている。これも削除を試みたが権限エラーで完全には消えなかった。**成果物には影響しない**残骸である。
6. 2026年5月分・問14（生命保険料控除の計算）、2025年5月分・問39（消費税の基準期間の判定）は、制度の重畳適用や「または」条件の解釈が複雑で、解説内で「制度の一般原則」と「公式模範解答」の整合性について正直な注記を入れている（`FULL_AUDIT_REPORT_FP2.md`参照）。次工程で人間のFP2級有資格者によるレビューを推奨する。
