# S1 Capture / Tracking｜実機受入ゲート

更新: 2026-08-15
対象branch: `scaniverse/s1-capture`

この文書はS1のhuman-only gateを固定する。GitHub ActionsやSimulatorがPASSしても、この実機確認を代替しない。

## 証拠の取り方

原則、以下を順番に操作した**画面録画1本**でよい。各ケースの途中でアプリが落ちた、表示が固まった、生成ボタンが出ない、明らかな位置飛びが起きた場合はそのまま録画を残す。

S1では3D生成そのものの最終画質はS2/S3担当だが、resume/relocalization後に二重化・大きな位置破綻が起きていないかはS1でも確認する。

## A. 対象物capture

### A1｜全周撮影が完了できる
1. 机上の模様・凹凸がある小物を置く。
2. 「新しくスキャン」を開始する。
3. 対象を中央付近に保ち、ゆっくり一周する。
4. 途中で少し高い位置・低い位置を混ぜる。

PASS:
- 片側だけでは完了扱いにならない。
- 一周＋高さ差を与えると「停止して生成へ」が出る。
- 同じ場所で端末を回すだけではcoverageが進み切らない。

### A2｜片側だけでは誤合格しない
1. 新規scanを開始する。
2. 対象の正面〜片側だけを広く動き、向きや高さを変える。
3. 反対側へ回らない。

PASS:
- 移動量や撮影枚数が多くても完了扱いにならない。
- 反対側へ回るようガイドされる。

## B. Scene capture

### B1｜室内
1. 部屋で新規scanを開始する。
2. 位置を移しながら複数方向を重ねて撮る。

PASS:
- 対象物の「一周」を要求され続けず、scene経路でcoverageを満たせる。
- 同じ位置から回転するだけでは完了しない。

### B2｜屋外
1. 屋外の十分明るい場所で新規scanを開始する。
2. 位置を移し、複数方向を重ねて撮る。

PASS:
- trackingが通常状態なら連続撮影できる。
- 大きなpose jumpでcoverageが急増しない。
- scene経路で完了できる。

## C. 距離適応

### C1｜近距離 / 遠距離
同一対象を近距離と少し離れた位置でそれぞれ新規scanする。

PASS:
- 近距離で小さな移動が全く採用されない状態にならない。
- 遠距離でほぼ同一位置の過密frameだけが増え続けない。
- 通常速度で歩いたときに操作不能な待ち時間がない。

## D. Resume / Tracking recovery

### D1｜一時停止 → 再開
1. 途中まで撮影する。
2. 「一時停止」。
3. 数秒後「撮影を再開」。
4. 前に撮った場所を映してから続ける。

PASS:
- 新規scanとして0から始まらない。
- 既存coverage・frameが維持される。
- 復旧中はすぐ新規frameを取り込まず、位置復旧後に続行する。

### D2｜停止 → 撮影追加
1. coverageを満たして「停止して生成へ」。
2. 生成前画面で「撮影を再開して追加」。
3. 別角度を追加する。

PASS:
- 既存scanへ追加される。
- coverageやpose座標系がリセットされない。

### D3｜バックグラウンド → 復帰
1. 撮影途中でホーム画面などへ移る。
2. アプリへ戻る。
3. 前に撮った場所を映す。

PASS:
- アプリが落ちない。
- 復帰直後に無条件でframeを追加しない。
- relocalization後に同じscanとして続行できる。

### D4｜tracking loss → relocalization
1. 撮影途中でカメラを一時的に特徴の少ない面へ向ける、または速く動かしてtracking limitedを意図的に発生させる。
2. 前に撮った特徴のある場所へ戻す。

PASS:
- tracking loss中はframe採用が止まる。
- 復旧後に続行できる。
- 復旧だけでcoverageが不自然に飛ばない。
- 生成後に明らかな二重化・大規模な位置ずれが出ない。

## E. Long scan / frame limit

### E1｜長時間・大量frameで行き止まりにならない
長く撮影して90秒を超える。可能なら大量frameまで継続する。

PASS:
- 90秒で長時間警告が表示される。
- 180秒でより強い停止推奨が表示される。
- soft frame limit到達後もcoverage不足なら、未撮影方向・高さだけは救済追加できる。
- coverage達成後は追加撮影が抑止され、「停止して生成へ」を選べる。

## F. LiDAR-capable device only

### F1｜LiDAR ON / OFF
LiDAR対応端末が利用できる場合のみ実施する。

PASS:
- ONではDepth取得表示が成立する。
- OFFではDepthなしでもRGB＋ARKit poseで撮影を続けられる。
- 切替によってクラッシュしない。

LiDAR対応実機が手元にない場合はこの1項目だけ`DEVICE_UNAVAILABLE`としてS4/S8のLiDAR実機ゲートへ引き継ぐ。未確認をPASS扱いしない。

## 判定

- `PASS`: A1/A2/B1/B2/C1/D1/D2/D3/D4/E1を実機で満たす。F1は対応端末がある場合にPASS。
- `FAIL`: crash、resume後のpose破綻、片側誤合格、scene完了不能、soft limit行き止まりのいずれかが再現。
- `DEVICE_UNAVAILABLE`: F1のみ許容。S1を完全PARITYとはせずLiDAR実機証拠を後続へ明示移管する。
