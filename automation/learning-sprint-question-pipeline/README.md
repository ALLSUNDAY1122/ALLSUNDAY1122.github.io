# 学びスプリント｜問題生成・監査パイプライン v1.1

目的は、資格アプリごとに毎回発生する「必要量の問題・正解・解説作成」「試験回相当×科目の分類」「水増し監査」「法令・利用条件監査」を共通化することです。

## 必須原則

- 必要問題数は `本試験1回分の問題構成 × 対象アプリで決めたrounds` で先に固定する。`rounds` は資格ごとの `learning-sprint-audit.json` を正本とし、3回固定にしない。
- 「N年分相当」は問題量・構成の表現であり、過去問本文をそのままN年分転載する意味ではない。権利根拠が明確でない限り、公式問題は論点・出題傾向の一次資料として使い、アプリ問題は独自表現・独自解説とする。
- 問題数不足を、同じ論点の言い換え・正誤反転・数値だけ変更した問題で埋めない。
- 問題・選択肢・正解・解説を1セットとして管理する。
- 各問題に `round`、`subject`、`topic`、`source_url`、`reference_date`、`origin_type`、`rights_basis` を持たせる。
- 法令・制度・公式手引き等の一次資料を根拠にする。市販教材や他社アプリを直接の作問原稿にしない。
- 公式過去問をそのまま利用する場合は、権利者が許可していることを `rights_basis` に明記する。
- UIの「試験回相当×科目」、総セット数、総問題数はデータから自動生成し、画面側へ固定件数を書かない。

## 標準データ

各資格リポジトリまたは各資格フォルダに次の2ファイルを置きます。

- `learning-sprint-audit.json` : rounds、科目別必要問題数、問題バンクの場所
- 問題バンクJSON : 問題・選択肢・正解・解説・根拠等

設定例は `exam-config.example.json` を参照してください。

## 問題ID

推奨形式：`<資格略称>-R<回>-<科目略称>-<連番>`

例：`EISEI2-R4-HOREI-001`

## 問題として別物と認める基準

同じ論点でも、次のように問う能力が実質的に異なる場合は別問題として扱えます。

- 基本知識
- 適用判断
- 例外
- 計算
- 複数条件の比較

一方、次は原則として水増しです。

- 肯定文を否定文へ変えただけ
- 正しいもの／誤っているものを入れ替えただけ
- 固有名詞・金額・日数等だけを変えただけ
- 選択肢の順番を変えただけ
- 同一の正解根拠をほぼ同じ文章で聞き直しただけ

## 自動監査の合格条件

`validate_questions.py` は少なくとも次を検査します。

- 総問題数が `rounds × 1回分問題数` と一致
- 各round×各科目の件数が一致
- 問題ID重複0
- 問題本文完全一致0
- 高類似問題0（初期閾値 0.90）
- 必須フィールド欠損0
- 選択肢数不足0
- 正解インデックス不正0
- 解説欠損0
- 根拠URL欠損0
- 法令・制度基準日欠損0
- 権利根拠欠損0

機械監査でPASSしても、法的適否・正答の内容そのものは一次資料に照らしたAI監査／人間の最終承認対象です。

## ループ

1. 試験構成・rounds・必要数を確定
2. 論点マップ作成
3. 一次資料確認
4. 必要数の問題・正解・解説を作成
5. 自動監査
6. FAIL箇所を修正
7. 再監査
8. 法令・著作権・正答内容を別監査
9. PASS後、アプリが `round` と `subject` から自動分類表示

問題・正解・解説・根拠を変更した場合、問題品質ループのPASS状態は失効し、再監査します。
