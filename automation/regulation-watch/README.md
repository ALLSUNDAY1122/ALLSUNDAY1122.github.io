# 学びスプリント 制度改定監視

公式一次情報のページ変更を毎日自動で確認し、変更があったときだけGitHub Issueを作成する仕組みです。

## 動作

1. GitHub Actionsが毎日06:17 JSTに実行される。
2. `sources.json` に登録した公式URLを取得する。
3. script/style/navigation等を除いた本文テキストを前回スナップショットと比較する。
4. 初回は基準スナップショットを保存するだけでIssueを作らない。
5. 2回目以降に差分があれば、影響候補資格・監視論点・差分をGitHub Issueへ自動記録する。
6. URL取得が3回連続で失敗した場合もIssueを作る。
7. スナップショット・状態・差分ログはGitHubへ自動コミットする。

## 重要な前提

ページ変更の検知は「法改正が確定した」という意味ではありません。レイアウト変更や通常のお知らせ追加でも検知します。Issueが作成されたら、公式一次資料で次を確認します。

- 改定内容
- 公布日
- 施行日
- 試験への適用日・基準日
- 影響する資格
- 影響する問題ID

影響ありの場合は、問題文だけでなく、選択肢・正解・解説・根拠・基準日を一括して更新し、別工程で監査します。

## 監視対象の追加

`automation/regulation-watch/sources.json` に次の形式で追記します。

```json
{
  "id": "unique_id",
  "name": "公式ページ名",
  "url": "https://example.go.jp/official-page",
  "qualifications": ["資格名"],
  "topics": ["制度名", "試験範囲"],
  "priority": "high"
}
```

`id` は後から変更しないでください。変更すると別の監視対象として新規ベースラインが作られます。

生命保険一般課程・専門課程など、公式監視URLをまだ確定していない資格は追加調査後に `sources.json` へ登録します。

## 手動実行

GitHubの Actions → Regulation Watch → Run workflow からいつでも実行できます。

## 費用設計

AIは定期監視には使いません。通常時はWeb取得と差分比較だけで終了するため、ChatGPT・Claude・Codexのトークンを消費しません。変更を検知したときだけ、必要に応じてAIで影響判定・問題ID抽出・修正監査を行います。
